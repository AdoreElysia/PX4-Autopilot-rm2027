## 0. 一句话总结

**这块飞控板没有把任何一对能做硬件 I²C 的引脚引到插座上**（§2 有完整证据），
所以 VL53L0X 用**软件 I²C（bit-bang）**：两根普通 GPIO 自己拉时序。

接线只有 4 根，插在 **U18 座（UART7 那一路）** 上，一根 4 芯 GH1.25 线同时供电和通信：

```
U18 丝印(左→右)   5   →  模块 VIN
                  R   →  模块 SDA      ← MCU = PE7（原本 UART7_RX）
                  T   →  模块 SCL      ← MCU = PE8（原本 UART7_TX）
                  G   →  模块 GND
          模块 GPIO1 悬空；XSHUT 接 VIN
```

**这四个脚是临时接法**（用户明确说明：以后硬件会改）。花掉的是 **UART7**（= ESC3 的串口遥测）。
硬件改版引出真正的 I²C 之后，删掉驱动目录 + 三处配置即可（§9）。

**2026-10-18 实况**：已烧进板子并跑通 —— `model_id = 0xEE`（确实是 VL53L0X）、
**20 Hz 连续 30 分钟以上、软件 I²C 零错误**、距离读数随环境变化（§4.4）。
没有串口时用 `~/RM2027/vl53-status.sh` 从 SWD 看数据（§5.1 看法 A）。

**测试结论（最终）**：
- 量程：**2 m**（数据手册 Table 12：室内白墙 200 cm+，灰卡 80 cm，室外阴天 80/50 cm）；
- 速率：本驱动 **20 Hz** 固定（芯片默认 33 ms 时间预算，理论最高 ~30 Hz，最短 8 ms 周期）；
- 读数超过量程时输出 **8191 mm + 非 0/11 状态**（正常现象）。
- ❗ **临时引脚已于测试后撤销**：UART7（PE7/PE8）恢复给 ESC3 串口遥测，见 §11。

### 1.1 ★ 上电前必须做的一个测量（会烧东西的那一步）

**VL53L0X 芯片的 AVDD 绝对最大值是 3.6 V**（数据手册 §5.1）。
模块上写着 `VIN`、说明"2.8~5 V 可用"，**前提是模块背面有一颗 3.3 V LDO**
（常见 XC6206 / 662K / RT9193）。若模块是 3.3 V-only 的版本，直接给 5 V 会**烧芯片**，
而且它的 I²C 上拉也会被拉到 5 V → 反过来打 STM32。

**做法（30 秒，只接两根线）**：模块只接 `VIN`(U18.1) 和 `GND`(U18.4)，
用万用表量 **SCL 对 GND 的电压**：

| 读数 | 含义 | 怎么办 |
|---|---|---|
| ≈3.3 V（≤3.5 V） | 模块有 LDO，I²C 电平是 3.3 V | ✅ 再把 SDA/SCL 接到飞控 |
| ≈5 V | 模块没有 LDO，I²C 电平就是 5 V | ❌ 不要接飞控；得改用 3.3 V 供电（本板插座上没有 3.3 V，需要另想办法） |

> 本驱动**刻意不开** STM32 的内部上拉，I²C 上拉完全靠模块板载的 4.7 kΩ。
> 好处是"读不到高电平"就等于"模块没插好"，见 §5 的 `test`。

## 2. 为什么只能用软件 I²C（这一节是本次决策的全部证据）

### 2.1 先看 STM32H743VIT6（LQFP100）上到底哪些脚能做 I²C

来源：NuttX pinmap `platforms/nuttx/NuttX/nuttx/arch/arm/src/stm32h7/hardware/stm32h7x3xx_pinmap.h`
（"I2C" 那一节，含全部 AF 选项）。**去掉 LQFP100 上不存在的 PF/PH 脚**之后只剩：

| 外设 | SCL 可选脚 | SDA 可选脚 | 本板情况 |
|---|---|---|---|
| I2C1 | PB6, PB8 | PB7, PB9 | **全都没引到插座**（PB7/PB8 只有底层测试点，PB9 连网络都没有） |
| I2C2 | PB10 | PB11 | 板载气压计 SPA06 在用 |
| I2C3 | PA8 | PC9 | PC9 = ESC4 的 DShot；**PA8 是悬空单点网络、没引出** |
| I2C4 | PD12 | PD13 | 板载磁罗盘 IST8310 在用 |

### 2.2 再看每个插座上的信号脚能不能做 I²C

把原理图网表（导出自嘉立创 EDA，见 §2.3）里**每个插座成员的网络**与上表交叉核对，
结果（用脚本跑过，不是目测）：

| 插座 | 用途 | 信号脚落在哪些 MCU 脚 | 有 I²C 能力吗 |
|---|---|---|---|
| U13 / U11 / U14 / U15 | ESC1..4 | PC0/PC1/PC4/PC5（电流）、PA11/PC7/PE7/PE0（遥测RX）、PE11/PE13/PC8/**PC9**（DShot） | **只有 PC9 能做 I2C3_SDA** |
| U16 | 遥控 | PD2 / PC12 | ✗ |
| U17 | TEL1（MAVLink） | PD8 / PD9 | ✗ |
| U18 / U19 / U20 / U21 | ESC1..4 遥测串口 | PE7/PE8、PE0/PE1、PC6/PC7、PA11/PA12 | ✗ |
| H1 / H2 | SPI2 / SPI3 | PD3/PC2/PC3、PC10/PC11/PB2 | ✗ |
| H14 | 遥控反相输入 | DUS（接在三极管基极上，不是 GPIO 直连） | ✗ |
| CN1 / CN2 | CAN1 / CAN2 | 经收发器后的 CANH/CANL，MCU 侧 PD0/PD1、PB12/PB13 没引出 | ✗ |
| CN3 / CN6 | SWD | PA13 / PA14 | ✗ |

**结论**：整个板子上，**唯一**引到插座的 I²C 引脚是 `PC9`（U15 的 3 号脚），
而它现在被 ESC4 的 DShot 占着；更致命的是它的搭档 `I2C3_SCL = PA8`
**根本没引到任何插座**（原理图上是"单点网络"，PCB 上只有一个底层测试点 `T1_C1`）。

⇒ **只用现有插座，硬件 I²C 在物理上不存在。**

### 2.3 本次用到的证据文件（可复查）

| 文件 | 是什么 | 怎么再生成 |

| `docs/vl53l0x/FMU_netlist.net` | **飞控板**完整网表（Protel 格式，102 KiB） | 嘉立创 EDA 打开工程 → 打开 FMU 原理图页 → 用 API `sch_Netlist.getNetlist("Protel2")` 导出 |

| `docs/vl53l0x/FMU_pcb_source.txt` | **飞控板 PCB 源文件**（829 KiB）：焊盘/过孔/丝印/坐标 | API `sys_FileManager.getDocumentSource()`（需先打开 PCB1） |
| `docs/vl53l0x/netlist_raw.json` | 上面第一项的原始 API 返回 | — |

从 PCB 源里得到的两条关键事实（本次判决的依据）：
1. **插座丝印顺序**：`U18` 从左到右是 `5 / R / T / G`（= pin1 5V、pin2 RX、pin3 TX、pin4 GND，
   由网表 `U18-1..4` 与丝印文字坐标逐一对上；`U16`/`U19` 两个 180° 的座反着排，交叉验证一致）。
2. **过孔是盖油的**（设计规则 `viaTopExpan/viaBotExpan = -1000`），**不能当过孔焊点用**；
   而测试点焊盘有开窗（`padTopExpan/padBotExpan = +2`），能焊。

### 2.4 为什么软件 I²C 是安全的（芯片手册允许）

依据 DS11555 Rev6 §4.1 Table 4：

| 参数 | 手册值 | 对本方案的意义 |
|---|---|---|
| `FI2C` 工作频率 | **最小 0 Hz**，最大 400 kHz | **没有最低速度要求**，慢一点无所谓 |
| `tLOW / tHIGH` | ≥1.6 µs / ≥0.6 µs | 只有下限，软件拉线随便满足 |
| `tBUF` 两次传输间隔 | L0X 手册写 **1.3 ms**（见下） | 本驱动轮询间隔 5 ms，任何解释下都满足 |
| 时钟延展 | 手册无此参数 | 不用实现 |

> ⚠️ **手册里那个可疑的 `tBUF = 1.3 ms`**：同一颗芯片家族的 **VL53L1X 数据手册把同一参数写成
> `1.3 µs`**（正确值），而 ST 官方 API、上游 PX4 `vl53l0x` 驱动、Pololu / Adafruit 库
> **全都是"寄存器背靠背访问"且实测可用**。若真需要 1.3 ms 间隔，任何库都不可能工作
> ⇒ 判定为 L0X 手册的单位笔误。**结论：不按它设计**，但记一笔在这里。


> —— ① ACK 要保持到随后的 SCL 下降沿；② 主机回 NACK 后从机必须吐出总线。
> 另外"I²C 在 START/STOP 前必然有一个空 SCL 脉冲"，所以判据放宽到"字节边界 ±1 拍"。

另有一条**独立于驱动的旁证**（读 GPIOE 寄存器，不是读驱动变量）：
`MODER` 显示 PE7/PE8 = 通用输出、`OTYPER` = 开漏、**`PUPDR` = 全 0（我们这边没有任何内部上拉）**，
而 `IDR` 里 PE7(SDA) 读回**高** ⇒ **有外部器件在把它拉高**（模块的 4.7 kΩ 上拉）⇒ 模块有电。
> 这条曾在排查"模块到底有没有通电"时用上：驱动侧没有任何上拉，所以"线上能读到高"只能是模块拉起来的。

### 4.5 TEL1 串口链路：飞控在发，问题在线上（待处理）

想用 nsh 看数据得让 TEL1 的 USB-TTL 通。实测：

| 项 | 结果 |
|---|---|
| PC 侧串口设备 | `/dev/ttyUSB0` 存在（适配器被识别） |
| 读 3 秒原始字节 | **0 字节**（收不到任何东西） |
| 飞控侧 USART3 寄存器 | `CR1=0x2000002d`（UE/TE/RE 全开）、`BRR=0x824` → **57600**、`ISR` 里 `TEACK/REACK=1` 且 **TX FIFO 里还有待发数据** |

**进一步判决实验（2026-10-18 晚，把两个方向分开验证）**：

| 实验 | 做法 | 结果 | 结论 |
|---|---|---|---|
| PC → 飞控 | 先 halt CPU（中断跑不了），再从 PC 连发 81,056 字节，读 USART3 `ISR` | **`ORE`(bit3)=1、`RXNE`(bit5)=1** | **PC→飞控通**：适配器 TX、地线、U17 `R` 都好 |
| 飞控 → PC | PC 侧 `cat` / pyserial 严格 raw 各读 3~4 秒 | **0 字节** | 这一段不通 |
| 飞控 TX 是否真在发 | halt 后读 `ISR`：**`TXFE` = bit 23 = 1（TX FIFO 空）** | 数据已全部发完，不是"卡在 FIFO" | 飞控正常在发 |
| 引脚 | `MODER`=复用、`AFR[1]=0x00440077` → PD8/PD9 = **AF7 = USART3** | ✓ | 引脚映射正确 |
| 焊盘/走线 | 临时把 PD8 改成 GPIO 输出，驱动低/高再读 `IDR` | 拉低读到 0、拉高读到 1（恢复后 `MODER` 已复位） | PD8 与它所在的网络正常 |

> ⚠️ **踩过的坑：`TXFE` 是 ISR 的 bit 23，不是 bit 8**（见 `stm32h7x3xx_uart.h:364`）。
> 我一开始按 bit8 判读，得出"FIFO 里有待发数据"的错误结论，多绕了一圈。

⇒ **飞控侧全部正常；断点只在"PD8 → U17 `T` → 适配器 RX"这一根线/接触上**（或适配器的 RX 输入本身）。
下一步（按省事排序）：
1. 万用表量 U17 丝印 `T` 对 GND：空闲应 **≈3.3 V**（飞控在发，会轻微抖动）。
   - ≈3.3 V ⇒ 飞控到插座都好 ⇒ 换那根信号线 / 检查接触 / 或短接适配器 TXD+RXD 做回环自测；
   - 0 V ⇒ 插座接触或板内走线，再来查。
2. 交叉规则再重申一次：适配器 **RX → 丝印 `T`**、适配器 **TX → 丝印 `R`**、**GND → `G`**；
   U17 是**竖着**的，丝印从上到下是 `G / R / T / 5`（不是横着那些座的顺序）。
3. **别插 U18**（那是传感器的 I²C 口）。

### 4.6 两次"驱动静默停住"的观察 + 已加的健壮性

2026-10-18 晚观察到一个现象：驱动连续跑了 47 分钟（`published=56701`）后，**状态块冻结**，
但整机是活的（halt 后 PC 停在 NuttX 的 idle 循环 `nx_start`、CFSR/HFSR 全 0、另一个串口照常工作）。
原因未定位（怀疑与当时反复 halt CPU 有关；`wq:I2C3` 线程阻塞但没有 HardFault）。

为此给驱动加了两处防御（已编译、已烧录）：

| 改动 | 位置 | 作用 |
|---|---|---|
| 忙等加**硬上限**（约 1 ms 的迭代数） | `vl53l0x_softi2c_main.cpp` 的 `delay_half_period()` | 即使 hrt 时间异常也不再可能永久卡死工作队列 |
| 初始化失败**每 15 s 自动重试** | `VL53L0XSoftI2C.cpp` 的 `Start()` / `Run()` | 传感器断电/复位/被搞卡之后能**自己恢复**，不需要控制台敲 `start` |

另外观察到：反复 halt CPU 会把传感器的测量引擎搞进降级态（6.2 Hz、`range_status=6`），
**断电/复位后自行恢复**（实测复位后回到 19.9 Hz、`range_status=11`、0 错误）。
⇒ 用 §5.1 的脚本读状态时，如果发现 `published` 不再增长，先**给模块断电重上电**再判断。

**先 stop，再 test**（test 会自己驱动总线）：

## 6. 已知代价与风险（都属"临时方案"范畴）

| # | 项 | 说明 | 严重度 |
|---|---|---|---|
| 1 | **UART7 从此不能当串口用** | ESC3 的串口遥测没有串口了（`rc.board_sensors` 里那句注释写的就是这个） | 中（未做电机联调，暂时无影响） |
| 2 | **U14.2 与 U18.2 是同一根线（PE7）** | 往 U14 接 ESC3 遥测线会和 SDA 抢线 | 中（接线时注意） |
| 3 | 软件时序、占 CPU | 按 100 kHz 估算约 **5 ms / 50 ms 周期**（≈10% 一个核），以"连续 ≤1.4 ms 的忙等块"出现。已放在**独占队列 `wq:I2C3`** 上（本板没有 I2C3 外设），不挤别的模块；嫌重就把 `-f` 调到 200（时间减半，字节数不变） | 低 |
| 4 | 没有用中断脚 | `GPIO1` 悬空，靠轮询 `RESULT_INTERRUPT_STATUS`（每 5 ms 看一次，超时 150 ms） | 低（20 Hz 够用） |
| 5 | XSHUT 直接接 VIN | 上电后芯片一直工作，不能软复位/改地址 | 低（单颗传感器） |
| 6 | 模块可能是 VL53L1X | 那本驱动**驱动不了**（L1X 是 16bit 寄存器空间 + 另一套 API）。驱动会打印 `model id != 0xEE` 明确报出来 | 待用户确认 |
| 7 | 5 V 供电的前提 | 见 §1.1，**必须先量 SCL 对地电压** | ★ 会烧硬件 |
| 8 | 引脚是临时的 | 用户明确说了硬件以后会改 | — |

## 7. EKF2 怎么用它（要参与定高时）

驱动只负责发 `distance_sensor`（`orientation = 25 向下`）。是否参与融合由 EKF2 决定：

| 参数 | 默认 | 说明 |
|---|---|---|
| `EKF2_RNG_CTRL` | **1（条件模式）** | 已在默认值上：低速（<`EKF2_RNG_A_VMAX`）低空（<`EKF2_RNG_A_HMAX`）时用测距做高度源 |

| `EKF2_RNG_GATE` | 5 SD | 新息一致性门 |

上手顺序建议：
1. 先只看 `listener distance_sensor`：**手挡在传感器前面，读数要跟着变**；
2. 再看 `listener estimator_status` 里 `hagl` / `rng_...` 字段有没有动；
3. 最后才考虑改参数（默认值先别动）。

> ⚠️ 地面/桨叶反射、日光下 2 m 以内的量程都会影响 ToF，别急着拿它当主高度源；
> 如果要精确贴地高度，官方更推荐 `MPC_ALT_MODE`（见 `EKF2_RNG_CTRL` 参数说明原文）。

### 11.3 这次踩过的坑（给下一个人省时间）

| 坑 | 事实 / 教训 |
|---|---|
| **`TXFE` 是 ISR 的 bit 23**，不是 bit 8 | `stm32h7x3xx_uart.h:364`。按错位判读会得出"FIFO 里有数据/没在发"的相反结论 |
| `mdw` 在本机 OpenOCD+ST-Link 下**无效** | 读内存只能 gdb `x/`；且读内存必须 halt 核 |
| **halt CPU 会把 VL53L0X 搞进降级态** | 反复 halt 后出现 6.2 Hz + `range_status=6`，**断电/复位后自愈** |
| 驱动曾"静默停住"一次 | 整机活着（PC 在 idle）、无 HardFault，但状态块冻结。已加两处防御（忙等硬上限 + 初始化 15 s 自动重试） |
| USB-TTL 链路"飞控在发、PC 0 字节" | 最后确认是**接触不良**：重新插紧即好。用"SWD 停核 + PC 灌字节看 ORE"能证明 PC→飞控方向是通的 |
| **不要用 `debug_array` 往 QGC 送自定义量** | 本树的 `debug_array_s::ARRAY_SIZE=58`，而 MAVLink `DEBUG_FLOAT_ARRAY` 只有 10 个槽位 ⇒ 发送循环有越界写风险（未修）。宁可用 `listener` |
| QGC 里 `DISTANCE_SENSOR` 只有 0.2 Hz | 不是传感器问题：57600 链路带宽不够，PX4 的 `_rate_mult` 把全部流打折。`SER_TEL1_BAUD=921600` 可解 |
| 本板**没有**硬件 I²C 引出 | 全板唯一引到插座的 I²C 脚是 PC9（ESC4 DShot），且搭档 PA8 未引出（§2） |
