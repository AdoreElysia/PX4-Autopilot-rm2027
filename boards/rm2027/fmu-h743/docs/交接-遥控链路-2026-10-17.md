## 0. 一句话总结

遥控器（WFLY ET16 Pro）和接收机（WFLY RF209S）**已经在发 W.BUS**，飞控的 UART5 也已按 **100 kbaud / 8E2** 正确配置、信号确实到达 PD2；
**唯一未解决的是极性**：实测 PD2 上是一路「空闲高」的**非反相**串流，而 PX4 解 SBUS/W.BUS 时会主动把 RX 反相（预期"空闲低"），所以解不出帧。
**下一步只需把信号线换到另一个输入口（U16.R ↔ H14.D）即可，无需改代码、无需重启。**

| 项 | 型号 | 备注 |
|---|---|---|
| 遥控器 | **WFLY ET16 Pro** | 2S 锂电或 2×18650；Type-C 可充电；开机=长按 POWER 3 秒（电压 6.6–8.6V，超范围开不了机） |
| 接收机 | **WFLY RF209S** | 9 路 PWM + 1 路自定义(PPM/W.BUS) + 1 路自定义(W.BUS2)；工作电压 3.7–8.4V |

手册（已下载在本地）：

- `~/RM2027/docs/遥控器手册/RF209S接收机_FCC-ID-TZVRF209S_用户手册.pdf`（2 页原厂手册，从 FCC 备案 fccid.io 的 Wayback 存档取得）

### 1.2 接收机侧设置（已完成，可用）

- 对码：接收机上电后**长按 SET 键 3 秒**（橙灯慢闪）→ 遥控器【通信设置】→【对码】→【内置高频头】→【开始】。
- 输出模式：**绿灯常亮 = W.BUS 模式工作正常**（蓝=PPM，紫=PWM；橙慢闪=对码中，红=无信号）。
- 端口规则（手册）：**PPM/W.BUS/W.BUS2 只能设在 8~9 端口**；模式 A 下 **端口 8 = PPM/W.BUS，端口 9 = W.BUS2**（W.BUS2 是"非标 S.BUS、频率不同"，不要用）。
- 也可在接收机上直接切模式：**按住 SET 键通电 → 短按切换 → 长按确认**。
- 3 针排针定义（手册引脚图）：**信号 / 正极 / 负极**。

### 1.3 飞控侧接口（关键）

RC 信号最终都落在 **PD2 = UART5_RX = `/dev/ttyS4`**。板上有两个入口，**极性相反**：

| 入口 | 丝印 | 说明 |
|---|---|---|
| **U16**（GH1.25 四针，顶层，板子上边缘 x≈1455mil） | **5 / T / R / G** | **直连** PD2。接收机信号→`R`，正极→`5`，负极→`G`，`T` 不接 |
| **H14**（2.54mm 三针排针，U16 右侧约 350mil） | **G / 5 / D** | 信号经 **NPN 反相器 Q17**（基极=H14.1 "DUS"，集电极=PD2 节点，R19 上拉到 3.3V） |

其他相关：

- U17（GH1.25 四针，丝印对应 USART3）= **TEL1 = `/dev/ttyS2`**，板子的调试/遥测口（跑 MAVLink，57600）。和 RC 无关，互不影响。
- 板上还有 `T1_C1`/`T1_C4` 丝印（PA8/PE14），**是空脚的测试点**，不是 ESC 信号，别照它接线。
- 丝印上 U16 旁边还有个 `UART3` 字样，是遗留标签；以 **5/T/R/G** 为准。

## 2. 协议结论（已核实）

- **W.BUS 与 SBUS/DJI DBUS 本质兼容**：100 kbaud、8 位数据、**偶校验、2 位停止位（8E2）**、16 通道。手册原文：`W.BUS：兼容标准S.BUS，2048分辨率（16通道）`。
- **PPM 在这块板上不可用**：`rc_input` 的 PPM 扫描被 `#ifdef HRT_PPM_CHANNEL` 包着，本板没有定义该宏。
- PX4 侧协议参数 `RC_INPUT_PROTO`：-1=Auto（默认）、1=PPM、**2=SBUS**、3=DSM、4=ST24、5=SUMD、6=CRSF、7=GHST。
- `RC_MAP_*` 上游默认全是 **0（未分配）**：所以"原始脉宽有值、但 `manual_control_setpoint.throttle` 恒为 0"是正常的，必须设映射或做 QGC 遥控器校准。

## 3. 已修复的板级 BUG（重要，别回退）

`rc_input` 依赖板级 `default.px4board` 里的 `CONFIG_BOARD_SERIAL_RC` 来给 `RC_PORT_CONFIG` 生成默认值。
**本板原来缺这一行** → `RC_PORT_CONFIG` 默认 0(Disabled)、可选值里连 ttyS4 都没有 → `rc.serial` 里 `SERIAL_DEV=none` → **RC 驱动根本不会启动**（接线再对也收不到）。

已在 `boards/rm2027/fmu-h743/default.px4board` 补上：

```text
CONFIG_BOARD_SERIAL_RC="/dev/ttyS4"
```

修复后实测：`RC_PORT_CONFIG = 300 (Radio Controller)`，`rc.serial_port` 生成 `/dev/ttyS4` 分支 ✓。

### 5.2 烧录（ST-Link / SWD）——注意双 bank

固件约 **1.56 MB**，而 STM32H743 的 Flash 是 **2×1MB 双 bank**；OpenOCD 默认只定义 bank0，直接烧会在 0x08100000 处报 `no flash bank found` → 校验失败。
**必须打开 `DUAL_BANK`**：

```bash
openocd -f interface/stlink-dap.cfg \
        -c "adapter speed 4000; set DUAL_BANK 1" \
        -f target/stm32h7x.cfg \
        -c "init; reset halt; program build/rm2027_fmu-h743_default/rm2027_fmu-h743_default.bin 0x08020000 verify; reset run; shutdown"
```

- App 起始地址 **0x08020000**（bootloader 在 0x08000000，参数在扇区 15 = 0x081E0000，烧 app 不会碰参数）。
- `interface/stlink.cfg` 是 HLA 版，**不支持 `mdw` 读内存**；读内存要用 **`stlink-dap.cfg` + gdb**（见 5.4）。

### 5.3 串口控制台（有 USB-TTL 时最好用）

板子没有编译串口 nsh 控制台，TEL1（USART3=/dev/ttyS2）跑的是 **MAVLink @57600**，所以用 PX4 自带的 shell 工具：

```bash
cd ~/RM2027/PX4-Autopilot
python3 Tools/mavlink_shell.py /dev/ttyUSB0 -b 57600
```

进入后可用：

```text
rc_throttle start      # 每 1 秒打印一行（全部 ASCII）
rc_throttle status     # 详细快照（含波形与 UART 寄存器）
rc_throttle stop
listener input_rc      # PX4 原始主题
param show RC_PORT_CONFIG     # 应为 300
param set RC_INPUT_PROTO 2    # 只扫 SBUS，锁定更快（可选）
param set RC_MAP_ROLL 1
param set RC_MAP_PITCH 2
param set RC_MAP_THROTTLE 3
param set RC_MAP_YAW 4
param save
```

### 5.4 无串口时：SWD 读状态（非侵入，halt 几十毫秒）

## 6. 实测数据（2026-10-17，作为基线）

固件版本：`rm2027_rc_status.version = 4`

| 项目 | 实测值 | 判读 |
|---|---|---|
| `RC_PORT_CONFIG` | **300** | 端口分配正确（Radio Controller = /dev/ttyS4）✓ |
| `input_rc.updates` | **0** | PX4 一帧都没解出来 ❌ |
| `listener input_rc` | `never published` | 同上 |
| 探针（不反相） | 192 字节 / **0 帧** | 有字节、解不出帧 |
| 探针（反相） | 120 字节 / 0 帧 | 同上 |
| **PD2 波形** | 96,371 点 / **25,000 µs**（≈4MHz 采样），**占空比 88.8% 高**，**160 个边沿 ≈ 6400 边沿/秒** | **100 kbaud 串流、约 50Hz 一帧、空闲高电平 → 非反相** |
| USART5 `BRR` | `0x04b0`（PCLK1=120MHz → USARTDIV=75） | **100 kbaud** ✓ |
| USART5 `CR1`/`CR2` | `0x2000142d` / `0x00032000` | 校验使能+偶校验、**2 停止位 → 8E2** ✓ |
| USART5 `ISR` | `FE=1, PE=1, ORE=0, RXNE=0` | 解析时帧错误/校验错 → 极性或字节被抢 |

**结论**：接收机输出正常（线路是好的、数据也在动），飞控串口参数也正确；差的是**极性**。

## 7. 根因分析（极性）

1. PX4 的 `rc_input` 在扫描 SBUS 时会调用 `rc_io_invert(true)`（`RCInput.cpp` 的 `RC_SCAN_SBUS` 分支）。
2. 本板没定义 `RC_INVERT_INPUT`，于是走 NuttX 的 `TIOCSINVERT`（本板 defconfig 已开 `CONFIG_STM32H7_USART_INVERT=y`）。
3. 因此 **PX4 需要 PD2 上出现的是"反相"信号（空闲低）**；实测是空闲高 → 反相后变成断线 → 全是帧错误。
4. 两个输入口极性相反：**U16 直连 / H14 经 Q17 反相**。当前接的那条，极性与 PX4 的期望相反。

**修法（二选一）**：

- **A（无需改代码）**：把信号线换到另一个输入口（U16.`R` ↔ H14.`D`），5V/GND 不动，**不用重启**；`rc_input` 一直在循环扫描，几秒内应锁定。判据：`PD2 wave duty` 从 **88.8% → ≈11%**，同时 `input_rc updates` 开始上涨、出现 `RC OK protocol=SBUS/W.BUS ch=16`。
- **B（改代码，一劳永逸）**：改 `rc_input`，让 SBUS 扫描**两种极性各试一次**（或给本板加 `RC_INVERT_INPUT` 板级钩子）。需要重编+重烧。

## 9. 已知坑（踩过的）

1. **缺 `CONFIG_BOARD_SERIAL_RC` → RC 驱动不启动**（已修）。
2. **烧录必须 `DUAL_BANK=1`**，否则 1MB 之后写不进去、校验失败。
3. **改板级配置后要干净重建**，否则参数表沿用旧的（PWM_MAIN_TIM1 缺失即此坑）。
4. **`mdw` 不可用**（HLA 传输），读内存走 gdb `x/`。
5. **模块的原始串口探针会和 `rc_input` 抢 UART 字节**：探针在开机 6 秒后若无数据才启动，跑两轮（3s+3s）就结束；它只用于"无串口时判断线上有没有信号"。有了控制台后建议不再使用（下一步可把 `probe_update()` 调用去掉）。
6. **`RC_MAP_*` 默认 0**：原始脉宽有值 ≠ `manual_control_setpoint` 有值。
7. **控制台中文乱码**：PX4 nsh 不显示 UTF-8 中文，模块输出已全部改成 ASCII。
8. `PPM` 在本板不可用（缺 `HRT_PPM_CHANNEL`）。
9. 接收机端口 9 是 **W.BUS2**（频率不同），别和 W.BUS 混用。
