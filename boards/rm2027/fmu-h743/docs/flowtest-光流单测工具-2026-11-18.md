# flowtest —— PMW3901 光流单独测试工具

> 日期：2026-11-18
> 状态：**代码已编译通过，未上板实测**
> 适用：`boards/rm2027/fmu-h743` 的**测试板**（只有主控 + 外围，未焊片载模块）
> 源码：`src/systemcmds/flowtest/`
> 相关文档：`docs/交接-光流PMW3901-2026-11-17.md`（正式 PX4 链路的接法）

---

## 0. 为什么要有这个工具

正式固件里光流要过四层才到 EKF：

```
pmw3901 驱动 → sensor_optical_flow
sensors 模块 → vehicle_optical_flow      ← 这层要陀螺 + 朝下测距
EKF2         → 只用 vehicle_optical_flow
```

其中 `sensors/VehicleOpticalFlow` 有两处硬依赖（源码核实）：

| 依赖 | 位置 | 用在哪 |
|---|---|---|
| `sensor_gyro` 积分出 `delta_angle` | `VehicleOpticalFlow.cpp:407` | 扣除机体自身旋转 |
| `orientation == ROTATION_DOWNWARD_FACING` 的测距 | `VehicleOpticalFlow.cpp:363` | 把角速度换算成线速度 |

**这块测试板没焊 IMU、没焊 VL53** ⇒ 这两样都拿不到 ⇒ `vehicle_optical_flow` 里
`distance_m` 是 NaN、光流被**静默丢弃**（不报错）。看起来就是"光流坏了"，
其实芯片可能是好的。

`flowtest` 就是把这四层全砍掉：

```
PMW3901 芯片 --SPI3--> flowtest --串口--> 你的电脑
                        ↑
                  固定高度 0.10 m
```

## 1. 接线

### 1.1 光流模块 → 板上的 5 孔排针

| 排针丝印 | MCU 引脚 | 模块 9 针 | 说明 |
|---|---|---|---|
| GND | — | GND | |
| SCK | PC10 (SPI3_SCK) | CLK | |
| MISO | PC11 (SPI3_MISO) | MISO | |
| MOSI | PB2 (SPI3_MOSI) | MOSI | |
| PE14 | PE14 (TIM1_CH4) | CS | 片选，低有效 |
| — | — | **VIN** | ★ 3.3V，从排针旁 `3.3V_H7` 焊盘飞线 |
| — | — | RST | 3.3V 或悬空 |
| — | — | MOT | 悬空（本工具不用中断） |
| — | — | **VRE** | ★ **不要接任何电源**（是模块 LDO 输出 ≈2V） |

排针位置（PCB 坐标，y 相同，从左到右）：
`TIM1_CH4@230`、`SPI3_MOSI@345`、`SPI3_MISO@497`、`SPI3_SCK@648`、`GND@800`

附近 3.3V 焊盘：`(402,-232)` 和 `(515,-232)`。

> ⚠️ 排针上标的 "PE14" 就是 MCU 的 PE14，PCB 网络名叫 `TIM1_CH4`。
> **PE14 不驱动任何电机** —— 四路 DShot 是 `PE13/PE11/PC8/PC9`（`timer_config.cpp:105-108`）。

### 1.2 输出串口：U21

`U21` = `WAFER-GH1.25-4PWB` = **USART2** = `/dev/ttyS1`：

| U21 针号 | 网络 | 方向 |
|---|---|---|
| 1 | 5V | 供电输出 |
| 2 | USART2_RX (U1.25) | MCU 收 |
| 3 | USART2_TX (U1.86) | MCU 发 |
| 4/5/6 | GND | |

接 USB-TTL（**收发要交叉**）：

```
飞控 U21.3 (TX)  →  USB-TTL RX
飞控 U21.2 (RX)  →  USB-TTL TX   （本工具只发不收，这根可以不接）
飞控 U21.4 (GND) →  USB-TTL GND
```

⚠️ **本板 `CONFIG_NO_SERIAL_CONSOLE=y`** —— 8 个串口的 `*_SERIAL_CONSOLE` 全部未设，
**没有任何串口控制台**。所以 `PX4_INFO`/`printf` 看不到任何东西，本工具
必须自己 `open("/dev/ttyS1")` 才能输出。这也是为什么默认就写死这个口。

## 2. 用法

```
flowtest                      # 等价于 id：读芯片 ID，打印结果
flowtest id                   # Product_ID 应为 0x49，Inverse_ID 应为 0xB6
flowtest start                # 后台采样，默认 /dev/ttyS1、10cm、10ms、100ms 一行
flowtest start -C             # CSV 格式（便于贴 Excel）
flowtest start -z 0.15        # 固定高度改成 15cm
flowtest start -d /dev/ttyS2  # 换输出口（如 U17）
flowtest stop
flowtest status
```

参数：

| 选项 | 默认 | 含义 |
|---|---|---|
| `-d <dev>` | `/dev/ttyS1` | 输出串口（U21） |
| `-B <baud>` | 115200 | 波特率 |
| `-b <bus>` | 3 | SPI 总线号 |
| `-z <m>` | 0.10 | 固定高度（米） |
| `-i <us>` | 10000 | 采样间隔 |
| `-p <us>` | 100000 | 打印间隔 |
| `-C` | 关 | CSV 输出 |
| `-n` | 关 | 跳过初始化寄存器序列 |
| `-F` | 关 | 强制启动（忽略 `/dev/pmw3901` 存在） |

输出示例（人类可读）：

```
# flowtest: bus=SPI3 cs=PE14 mode=0 2000000Hz dev=/dev/ttyS1 height=0.100m scale=385px/rad
# Product_ID(0x00)=0x49 OK Inverse_ID(0x5F)=0xb6
# init register sequence written
t=  0.10s dx=    0 dy=    0 q=  0 ang=(     0.0,     0.0) mrad/s vel=(    0.00,    0.00) mm/s
t=  0.20s dx=  -12 dy=    3 q= 28 ang=(  -311.7,    77.9) mrad/s vel=(  -31.17,    7.79) mm/s
```

CSV 输出：

```
# t_ms,dt_ms,dx_px,dy_px,squal,ang_x_mrad_s,ang_y_mrad_s,vel_x_m_s,vel_y_m_s
1020,100.0,-12,3,28,-311.7,77.9,-0.0312,0.0078
```

## 3. 单位换算（"固定高度"到底怎么用的）

芯片给的是**像素位移**，不是速度。三步：

```
rad   = px / 385            ← 385 来自 PX4 驱动 PMW3901.cpp:311-312
meter = rad × height        ← height 就是 -z，固定值
m/s   = meter / dt          ← dt = 实际累加时间
```

**为什么需要高度**：光流测的是**角度变化率**（弧度/秒）。同样走过去 10 cm，
离地 10 cm 时张角变化大、离地 1 m 时张角变化小。不除以高度，读数就与飞行高度耦合，
没法当速度用。PX4 靠激光测距实时提供这个高度；测试板没有，所以固定成常数。

⚠️ **10 cm 是数据手册的下限附近**：Table 3 工作距离 **80 mm ~ ∞**。
10 cm 只比下限高 2 cm，能测但容易失焦。**建议先试 15~20 cm**（`-z 0.15` / `-z 0.20`），
确认能出数据后再试 10 cm。

## 4. 验证判据

| 现象 | 判据 |
|---|---|
| `flowtest` | `Product_ID=0x49`、`Inverse_ID=0xB6` |
| `flowtest start` 静止 | dx/dy 接近 0，`q`（Squal）在几十以上 |
| 平移模块 | dx/dy 有响应，方向与移动方向相反（成像往后走） |
| `q` 一直很低（< 10） | 地面纹理不够 / 太近失焦 / 光线太暗 |
| `Product_ID` 不是 0x49 | 先查 VIN=3.3V、GND、四根 SPI 线、CS=PE14 |

**Squal（0x07）= 信号质量**：0 = 完全没特征（纯白墙、纯色桌面），
越高越可靠。测试时务必对着**有纹理**的表面（木桌、地砖、带图案的纸）。

## 5. 与 PX4 驱动的关系：不要同时跑

`Motion`(0x02) / `Delta_X/Y`(0x03~0x06) 是**读后清零**寄存器
（read-to-clear）：读走多少就没了。

所以 `pmw3901` 驱动和 `flowtest` **同时跑会互相偷走对方的运动量**，
两边读出来都是碎片，看着像"丢帧"。本工具启动时会检查 `/dev/pmw3901`，
存在就拒绝启动（要强制用 `-F`）。

⇒ 正确顺序：先 `pmw3901 stop`，再 `flowtest start`。

**当前默认配置已经考虑到这点**：`init/rc.board_sensors` 里
`pmw3901 start -s -b 3 -R 0` 已**注释掉**（测试板上正式链路本来也出不来数据）。
等 IMU / VL53 焊回来、要跑正式链路时，取消注释即可。

|---|---|---|---|

### 6.3 这块板上**没焊**的器件（测试板）

| 位号 | 器件 | 后果 |
|---|---|---|
| U2 | IST8310 磁罗盘 | I2C4 无器件 |

但**不要改** `default.px4board` 的驱动开关 —— 那是编译期配置，
以后焊回来还要用。）
